# Đo RAM, độ trễ và thời gian embed của bge-m3

Biên bản mốc, viết 2026-09-29 khi làm Task 12.2b (phần đo trên máy dev); viết xong thì đóng băng. Phần đo trên máy demo bằng `docker-compose.prod.yml` chưa làm vì file compose prod của Task 4.5 chưa có.

## Cấu hình máy đo

- Máy dev Windows 11: AMD Ryzen 7 8845H (8 nhân, 16 luồng), 31,3 GB RAM. Không có GPU dùng cho torch; chạy CPU.
- `torch 2.14.0+cpu`, `sentence-transformers 6.1.0`, model `BAAI/bge-m3` tệp `pytorch_model.bin` (fp32, 2.271.145.830 byte) đặt ở `models/bge-m3`.
- Danh mục: 11.413 mã HS 8 số (xem [biên bản nguồn](2026-09-29-kiem-chung-hs.md)); mô tả đem embed dài trung bình 136 token (p95 265, tối đa 521), gồm mô tả tiếng Việt và tiếng Anh đã ghép cấp cha.

## Kết quả

| Chỉ số | Giá trị | Cách đo |
| --- | --- | --- |
| Embed một câu truy vấn, p50 / p95 | 178 ms / 216 ms | `python -m app.ai.hs.embed --bench 30` |
| Embed một câu ở luồng phụ (như trong API) | 170–180 ms | script thử, cùng model đã nạp ở luồng nền |
| Toàn bộ một lần gợi ý qua API (tìm K + V + RRF + ghi log, chưa gọi LLM) | 0,41–0,49 s | 3 câu × nhiều lần, `POST /api/hs/suggest` |
| Embed cả danh mục 11.413 mã | 94 phút (16:52 → 18:26) | `python -m app.ai.hs.embed`, batch 64, có lúc máy chạy thêm test |
| RSS của `api` khi khởi động, chưa nạp model | 174 MB | `Get-Process` |
| RSS của `api` sau khi nạp model (chưa có truy vấn) | 817 MB | trọng số được map vào bộ nhớ, chưa chạm hết |
| RSS của `api` sau vài truy vấn embed | 1.993 MB | ổn định quanh mức này |
| Postgres (container `db`) | 254 MB | `docker stats` |
| Caddy / Mailpit | 20 MB / 33 MB | `docker stats` |

Tốc độ embed danh mục khoảng 2 mã/giây khi máy rảnh, chậm lại khi có tác vụ khác. Một lần embed lại toàn bộ chỉ cần khi đổi model hoặc đổi cách ghép văn bản; mỗi lần nạp lại danh mục chỉ embed các mã có mô tả đổi.

## Ngưỡng của plan và kết luận

- Ngưỡng: tổng RAM stack > 85% RAM máy demo, hoặc p95 embed ≥ 1000 ms thì chuyển sang bge-m3 bản ONNX.
- p95 embed là 216 ms, dưới ngưỡng 1000 ms.
- RAM của `api` khi đã dùng model khoảng 2 GB, cộng Postgres, web, worker và Caddy vẫn dưới 4 GB, tức khoảng 13% RAM máy dev. Chưa biết RAM của máy demo (ngưỡng 85% phụ thuộc máy đó).
- **Kết luận tạm: giữ fp32, chưa cần ONNX.** Phải đo lại trên máy demo khi có `docker-compose.prod.yml` (chạy `docker stats --no-stream` cho `api`, `db`, `web`, `worker`, `caddy`, `mailpit`), và ghi vào cuối biên bản này nếu con số khác. Nếu máy demo có dưới 8 GB RAM thì cân nhắc ONNX hoặc tắt `EMBED_PRELOAD` (gợi ý rút gọn chỉ còn full-text).

## Ghi chú

- Đo bằng script ngoài repo; số liệu ở đây là bằng chứng, không phải cam kết hiệu năng.
